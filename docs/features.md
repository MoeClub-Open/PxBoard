# 功能范围

以下说明对应 PxBoard 核心 `0.4.0` 及当前官方插件，插件接口版本保持 `1.0`。模式决定默认安装组合和使用入口，业务能力取决于实际安装并启用的插件。

## 核心与使用界面

| 模块         | 功能                                                                                                             |
| ------------ | ---------------------------------------------------------------------------------------------------------------- |
| 初始化与模式 | 自用、公益 / 分享、商业运营；按可信插件源中的组合解析依赖、后台安装启用、显示状态、失败重试；安装成功后切换当前模式 |
| 身份与权限   | 管理员与普通用户、登录退出、密码修改、密码找回、只读及读写 API 密钥、会话撤销                                    |
| 插件管理     | 在线源注册与启停、当前平台筛选、依赖安装、组合安装、权限展示、启停、重启、卸载、升级恢复与可选 Ed25519 发布签名  |
| 运行与记录   | 独立插件进程、插件数据命名空间、持久事件投递、失败重试、操作记录                                                 |
| 管理后台     | 按已安装插件组织导航、资源列表、筛选、排序、分页、表单、导出、二维码、深浅主题和移动端导航                       |
| 用户前台     | `/user` 独立导航；自身权益、流量与到期、订阅及可选的订单、余额、工单、帮助、兑换码与推广；按插件启用状态和对应功能开关显示 |
| 商业公开首页 | 未登录访客查看公开在售套餐、价格、额度和期限，登录或注册后继续选择的套餐                                         |

所有账号登录后默认进入用户前台 `/user`，管理员也从这里使用自己的服务。站点管理使用独立入口 `/admin`；只有主动打开管理页面时才进入后台。前台使用真实业务接口，不以支付返回页参数代替服务端订单状态。

## 官方业务插件

| ---------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `branding`       | 独立站点名称、Logo、网站图标；登录页、用户前台、管理后台、公开首页及浏览器标题统一使用 |
| `registration`   | 普通用户注册、全局注册开关与推广来源记录；不依赖商业插件 |
| `access`         | 用户访问账户、明确的不限流量标志、流量额度与累计、暂停、到期、节点分组、等级、限速、设备数、周期重置、按订单去重的权益发放与撤销 |
| `nodes`          | 节点与机器管理、机器密钥、协议及端口、NodeRS 原生接口与认证配置管理、Xray / sing-box 代理同步、流量倍率、重复流量批次去重、状态监控 |
| `subscriptions`  | 通用订阅按客户端选择 Clash / Mihomo、sing-box 或 URI 格式；按访问权益筛选节点；支持链接重置和可选的订阅验证 |
| `redeem`         | 兑换码、总次数与每账号次数、到期与禁用、兑换记录及中断重试；支持访问权益、追加流量、延长期限、重置流量和可选余额奖励 |
| `commerce`       | 套餐、订单快照、余额支付、人工收款确认、充值、余额账本、优惠码、个人折扣及退回余额 |
| `affiliate`      | 可选推广关系、推荐链接、个人返佣规则、佣金冻结与撤回、转入余额、现金提现申请及审批；依赖商业插件 |
| `payments`       | Stripe Checkout 和易支付、渠道管理、支付回调签名、金额与币种检查、重复回调处理、支付流水                                         |
| `audit`          | 域名及子域名、关键词、正则、IP 网段与协议匹配；记录、节点阻断或暂停账户；审计命中记录清理                                        |
| `support`        | 公告、使用文档、工单、回复和关闭；工单支持 Markdown、权限保护的图片上传及外部图片 / 视频链接 |
| `notifications`  | SMTP 邮件投递、密码找回以及订单和工单通知，可单独安装 |
| `captcha`        | 可选 Turnstile、hCaptcha、reCAPTCHA v2 人机验证；可保护密码登录、注册、找回密码和订阅；第三方登录在登录或注册开启时受保护 |
| `oauth`          | 可选 Google、GitHub、LinuxDO 登录、绑定与解绑；新账号遵循独立全局注册政策；已有绑定人工搬入，不随面板数据导入自动转换 |
| `import-sspanel` | 转换 SSPanel 用户、现有权益、余额、商品与订阅；可选节点；原始表归档                                                              |
| `import-v2board` | 转换 V2Board 用户、套餐周期、余额与订阅；可选节点及推广关系和佣金；原始表归档 |
| `import-xboard`  | 转换 Xboard 用户、新旧套餐价格、余额与订阅；可选统一节点、机器及推广关系和佣金；原始表归档 |

安装商业组合后仍需创建套餐、配置收款渠道并接入真实节点。安装插件不会生成虚构套餐、支付商户、节点负载或用户订单。

默认组合见 [使用模式](modes.md)。推广、OAuth 与人机验证在任何模式下都不默认安装；兑换码默认只装在公益 / 分享组合。品牌、注册、兑换码、推广分别有自己的数据和设置，商业插件不再重复提供这些入口。公益站点只用注册、访问账户、节点、订阅与兑换码即可运行，无需商业交易插件。

## 品牌、注册与兑换码

品牌在 `branding` 单独配置。普通注册由 `registration` 的全局开关决定，不随模式切换改变；注册不会自动赠送流量或套餐。关闭注册不影响已有用户登录，也不影响已有 OAuth 绑定登录或账户绑定。允许创建 OAuth 新账号还需要对应提供方允许注册。

用户先登录，再在用户前台“兑换码”提交兑换码。兑换记录先登记再发放，使用固定操作编号重试，避免网络中断后重复发放。访问权益、流量和期限奖励不需要商业插件；余额奖励通过商业钱包入账。后台管理兑换码和记录，钱包不重复提供兑换入口。旧 `sharing` 插件已由注册与兑换码插件分别替代；`sharing` 仅继续作为公益 / 分享模式 ID。

## 套餐与账户权益

一个套餐可以设置多个购买周期及各自的价格，期限按天、按日历月或长期计算，也可提供重置流量等选项。账户权益与商品定义分开存储，下单时保存选中的周期和价格快照，编辑套餐不会重写既有订单。

流量额度 `quotaGiB` 与 `unlimited` 分开表达。`quotaGiB=0` 且 `unlimited=false` 表示没有可用流量；不限流量需要显式启用。新建自用或公益 / 分享工作空间时，仅为尚无账户的管理员建立默认长期不限流量账户，已有账户与既有权益保留。

迁移账户保留原流量使用基线、到期与已识别的重置规则，包括重置日、按到期日重置、年度重置和源时区。SSPanel 的等级和等级到期单独保存。订阅令牌可保留，但订阅地址采用 PxBoard 自己的路径。

## 支付、余额与推广

用户创建订单后，可选择余额支付或已启用的在线支付渠道。在线支付返回 `/user/orders`，前台继续读取服务端订单状态；收到服务端确认并完成权益发放后才显示开通结果。未配置在线渠道时，不会模拟支付成功。

金额按百分之一单位的整数存储和传递。商业插件的“金额设置”可设置站点显示名称和符号，默认“元 / ¥”；更改显示不会换算数值或改变支付渠道结算币种。订单保存购买时的套餐与金额快照。相同购买请求可以通过稳定的 `requestId` 防止重复创建订单；流量、权益、充值和佣金分别使用稳定操作标识防止重复入账。

退款操作为“退回余额”：撤销对应订单的权益，再将金额记入用户余额。有更新的权益订单时，先处理较新的订单。充值订单不通过再次入账的方式退款。

个人折扣由商业插件计算订单价格。可选 `affiliate` 插件另行提供推荐链接、推荐人数、个人返佣比例、首次购买或持续返佣、冻结周期、可用佣金、自助转入余额和现金提现申请。转入余额由用户直接完成，无需管理员审批；处理中会自动重试，同一笔操作不会重复入账。现金提现可撤回待审核申请，由管理员审批并登记打款。现金转账由运营方在外部执行；面板不会自动向用户银行或支付账户打款。

未安装或停用推广插件时，套餐、订单、余额与支付继续工作，不产生新佣金；停用期间的订单不在以后启用时补发奖励。原推荐关系、佣金和提现记录保留。OAuth、注册或推广事件延迟不会阻止用户账号创建，接收插件按用户及订单标识避免重复归因和奖励。

## 节点接入与监控

| 接入方式                   | 配置与运行范围                                                                                                                                    |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| NodeRS                     | PxBoard 自有机器接口、多节点、用户与独立连接凭据、配置同步、持久流量批次、在线账户及主机状态上报；具体协议能力由所使用的 NodeRS / Aerion 版本决定 |
| 官方 `px-agent` + Xray     | 当前提供 TCP 下的 VLESS、VMess、Trojan、Shadowsocks 配置，可选 TLS 文件证书                                                                       |
| 官方 `px-agent` + sing-box | 当前提供 VLESS、VMess、Trojan、Hysteria 2 配置；流量查询使用 V2Ray API，需要支持该功能的内核构建及查询工具                                        |

官方代理会在替换运行配置前调用内核的配置检查。修改配置可能重启相应内核并中断现有连接。用户暂停、额度变化和审计阻断按同步周期生效，默认同步间隔为 30 秒。

`nodes` 的状态页根据最后心跳判断在线：120 秒内收到心跳视为在线；已停用、从未接入、离线与运行异常分别显示。普通用户只可查看自己有权使用的节点，管理员可以查看机器、心跳、错误与已上报的资源用量。

“节点设置 → 向用户展示节点状态”默认开启；关闭后隐藏用户状态入口并关闭用户状态接口，管理员监控、NodeRS 接入、流量回报和订阅继续运行。节点“启用”和“订阅显示”分别控制实际节点服务与订阅可见性，隐藏节点不会自动停止监听。共用父节点服务的订阅入口保留父子关系，避免重复启动监听。

CPU、内存、磁盘、交换空间和在线账户来自实际节点上报。目前这些主机负载数据由 NodeRS 提供；没有上报的数据保持为空。状态页不执行公网连通性探测、客户端延迟测试或吞吐量测试。

## 流量审计

审计处理连接目标元信息，不解密 TLS 或收集通信正文。官方 Xray 代理可以读取访问日志并产生审计命中；sing-box 可以接收阻断规则，当前没有将其访问日志转换为审计命中记录的采集器。NodeRS 的流量统计与在线账户上报也不等同于目的地址审计采集。

IP 网段规则需要实际目的 IP，不能用猜测的域名解析结果代替。规则能否在节点端阻断，取决于所使用的节点代理和内核配置能力。命中记录默认保留 7 天。

## 数据迁移

迁移分为冻结快照、预览与整批提交。用户、原密码信息和业务记录在同一事务中写入；暂存不完整、目标冲突或关键数据无法识别时阻断。已提交任务再次执行不会重复写入。未映射的旧字段与表保留归档，历史订单和支付信息不会触发重新扣款或开通。

SSPanel 各分支的商品开通规则差异较大，商品内容与购买限制保留，但先设为停售供核对。遇到尚不能执行的 V2Board / Xboard 限售或续费规则，也先保留并停售。节点与机器为可选迁移项，证书和节点本地配置仍需单独核对。

推广关系与佣金可选导入到独立推广插件。源用户有非零可用佣金但未选择推广导入时，预览会阻断，避免遗漏可提取金额。原邀请码与兑换码只归档，不自动降低原限制后启用；OAuth 和原版面板以外的客户端扩展也需单独接入。

已运行旧版 PxBoard 的站点，升级时使用官方插件仓库的 `tools/migrate-commerce-affiliate.ts` 搬移旧推广数据，使用 `tools/redeem-migrate/migrate.ts` 搬移旧分享和余额兑换数据；保留原金额、发放标识与账本，遇到冲突停止而不覆盖。不要重新导入整站用户或直接删除旧插件数据来代替升级。操作入口见 [部署文档](deployment.md#升级到-040)。

原编码密码和已识别的动态验证码配置可以迁移；动态验证码密钥缺失或无法识别时不会自动关闭验证。详细字段、来源差异、重试与恢复方式见 [官方迁移文档](../../PxBoard-Plugins/docs/migration.md)。

## 当前边界

当前产品不承诺覆盖 Xboard、SSPanel 或 x-ui 的所有历史版本及功能。以下内容尚未提供：

- 自动扣费续订、Stripe Billing、按剩余时长精细折算的升降级、税务发票、原支付渠道自动退款或自动现金打款。
- 多币种结算、PostgreSQL、多实例共享运行器和插件的操作系统沙箱。
- 任意第三方前端脚本包的在线加载；第三方插件主要通过声明式页面扩展界面。
- 完整的代理链与路由编辑器；官方 `px-agent` 尚未提供与 NodeRS 相同的扩展传输和证书管理能力。
- 新用户自行开通及管理动态验证码的完整设置界面、邮箱验证码注册、复杂客服团队权限和完整登录风控。

外部节点、支付商户、SMTP 服务及证书需要使用运营方自己的实际配置。面板的账户状态、后台任务和支付流水可用于核对处理结果，但不能替代外部服务本身的可用性。
