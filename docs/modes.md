# 使用模式与初始化

模式决定需要安装的功能和访客入口，登录后的默认入口统一为用户前台 `/user`。选择模式后，面板从配置的可信插件源读取对应组合，安装依赖并启用插件。模式不是单独的界面标签，也不包含虚构套餐或节点。

## 默认安装组合

| 模式     | 组合 ID    | 官方源中的基础功能                                                     |
| -------- | ---------- | ---------------------------------------------------------------------- |
| 自用     | `personal` | `branding`、`nodes`、`subscriptions` |
| 商业运营 | `business` | `branding`、`registration`、`nodes`、`subscriptions`、`commerce`、`payments`、`audit`、`support`、`notifications` |

以上组合会自动安装所需依赖，包括访问账户插件 `access`。具体组合由 `PxBoard-Registry/bundles.json` 定义。源中必须存在对应组合，以及满足版本要求和当前服务器平台的插件产物。模式安装使用同一个来源解析依赖，不把不同来源的同名程序自动混在一起安装。

推广返佣 `affiliate` 和第三方登录 `oauth` 均不随模式默认安装；商业模式也不默认安装兑换码。自用模式可以按需独立安装邮件通知，用于找回密码，无需安装工单。需要这些功能时在插件中心单独安装。迁移插件同样属于可选扩展，不会因为选择商业模式就自动读取旧面板数据。

## 首次使用

启动面板后访问面板地址，选择自用或商业运营，再创建管理员。没有预设账号或密码。

创建账户后进入功能安装页。页面列出本次需要的插件及逐项状态；完成安装和启用后，可以进入后台，两种模式都可打开用户前台。

默认使用[官方在线插件源](https://raw.githubusercontent.com/MoeClub-Open/PxBoard-Registry/main/index.json)，面板服务器能联网即可安装。源码开发时可显式设置 `-plugin-source http://127.0.0.1:8091/index.json` 使用本机源；这里的回环地址指面板服务器，不是浏览器所在电脑。自建源可通过启动参数、环境变量或安装页选择，配置见 [部署文档](deployment.md)。

安装所需程序必须来自可信来源。插件和面板服务使用同一个系统用户权限；发布签名可确认安装包由固定密钥签署，但不会把插件变成操作系统沙箱。

### 安装失败

安装失败不会删除管理员，也不会把当前模式切换成一个尚未准备完成的模式。页面保留具体错误，可以调整来源后重试。

| 情况               | 处理方式                                                                    |
| ------------------ | --------------------------------------------------------------------------- |
| 无法读取插件源     | 确认源服务正在运行，面板服务器可以访问填写的索引地址                        |
| 缺少所选组合       | 使用提供 `personal`和`business` 对应组合的源，或更新源的组合定义 |
| 缺少当前平台产物   | 在插件源仓库发布服务器实际的 `GOOS-GOARCH` 平台                             |
| 依赖版本不满足     | 更新并重新发布该来源中的相关插件，保持依赖一致                              |
| 发布签名检查失败   | 核对该来源的公钥与产物签名；不同发布者的源分别注册自己的公钥                |
| 插件无法启用       | 查看该插件错误及面板进程日志，处理后在安装页重试                            |
| 面板重启或安装中断 | 返回功能安装页重试；已完成的安装和业务数据保留                              |

组合会在下载前解析所需依赖和平台。后续某个程序下载或启用失败时，已经安装的其他程序可以保留；只有全部所需插件就绪才将模式标记为完成。

## 自用

自用模式默认提供站点品牌、节点、访问账户和订阅。安装成功后，访问插件通过后台事件为尚无访问账户的管理员建立长期、不限流量、默认节点分组的账户。管理员已经有账户时保留原有配额和期限。

在后台接入自己的节点，再生成订阅并导入客户端。不限流量与流量额度分开设置，`unlimited=true` 才表示不限流量；单独把额度填成 0 不会开放无限流量。

自用组合不要求商业、支付或用户服务插件。仍然可以在插件中心增加审计或其他扩展。

## 按需分享

在自用模式中，可以单独安装注册、兑换码和流量审计插件，向其他用户提供服务，无需安装商业交易或推广插件。注册、兑换码和访问账户分别控制；停用插件不会删除已有用户、兑换记录或权益。

从旧版升级时，原公益 / 分享模式自动归入自用模式，已经安装和启用的插件、用户、套餐及配置保持不变。

## 商业运营

商业组合安装完成后提供三个入口：

| 使用者     | 默认入口与工作                                                             |
| ---------- | -------------------------------------------------------------------------- |
| 未登录访客 | `/` 查看在售套餐，登录或在开放注册时创建账户                               |
| 普通用户   | `/user` 查看流量与到期、选择套餐、支付、订阅、订单、余额、帮助和工单 |
| 管理员     | 默认同样进入 `/user`；主动打开后台入口或点击“管理后台”时进入站点管理       |

首页 `/` 不会因管理员身份被替换为管理总览。已登录时进入用户前台；未登录的商业站点显示公开套餐。普通登录默认进入 `/user`，只有主动访问管理页面后发起的登录才返回对应后台页面。商业模式可在系统设置自定义后台入口，默认是 `/admin`，使用方式和恢复方法见[部署文档](deployment.md#后台入口路径)。

套餐选择可以在登录与注册之间保留。用户提交购买后先创建订单，再选择可用的余额或在线支付方式；在线支付返回用户订单页，实际结果由服务端支付回调和开通状态决定。

管理员仍需提供真实的业务配置：

- 接入节点并确认心跳、证书和客户端连接配置。
- 创建套餐，设置价格、期限、流量、节点分组和上架状态。
- 选择收款方式；在线支付需要配置真实商户渠道和回调。
- 在注册插件决定是否开放新账号，在商业插件设置套餐与价格优惠。
- 需要推广时另装 `affiliate`，配置返佣比例、首次或持续返佣及冻结周期；无需推广时保持不安装或停用。
- 在用户服务中发布帮助文档、公告并配置邮件投递。

套餐期限使用按天、按日历月或长期三种表达。套餐售价、余额和佣金接口以整数分传递，界面以元显示。流量加油包和流量重置是独立商品类型。

未配置支付渠道时不会提供可执行的在线充值或伪造支付成功；用户有可用余额时仍可用余额购买。安装推广插件后，现金提现由管理员审批并在外部打款，再登记结果，不会自动转账。商业站点需要兑换码时可单独安装 `redeem`，用户统一从“兑换码”进入，钱包不再重复提供兑换入口。

## 独立功能与开关

模式负责默认安装组合，已经安装的功能由插件启用状态及该插件的设置决定。

| 需求 | 配置位置与影响 |
| --- | --- |
| 站名、Logo、网站图标 | `branding` 的“品牌设置”；统一用于登录页、用户前台、后台及浏览器标题，核心设置不再重复提供品牌入口 |
| 是否开放注册 | `registration` 的“账户注册”；关闭后拒绝普通新账号及 OAuth 新账号，已有用户登录不受影响 |
| 第三方登录 | 单独安装 `oauth`，按提供方配置；允许新用户还需要全局注册开放与该提供方允许注册 |
| 兑换码 | 启用或停用 `redeem`；访问权益兑换不依赖商业插件，余额兑换需要商业钱包 |
| 推广、佣金和提现 | 启用或停用 `affiliate`；公益站可完全不安装，商业订单与节点继续由各自插件提供 |
| 用户节点状态 | `nodes` 的“节点状态 → 用户前台”中的向用户展示节点状态；关闭后隐藏用户入口并关闭用户状态接口，管理员监控、NodeRS 接入、流量统计和订阅继续运行 |
| 用户可见的机器状态 | `nodes` 的“节点状态 → 用户前台”中的用户可见状态项目；未选中的字段不会通过用户状态接口返回 |
| 浏览器访问订阅 | `subscriptions` 的“订阅访问”按 User-Agent 关键词返回伪装页面，可关闭或修改关键词；客户端标识可以伪造 |
| 节点运行与订阅显示 | 在节点记录中分别设置“启用”与“订阅显示”；隐藏订阅不会停止节点服务 |

停用插件同时停止其接口和新业务处理，历史数据保留。推广插件停用期间的订单不在以后重新启用时补发佣金。用户前台按已启用的插件显示入口，直接请求对应业务接口也要满足插件权限和开关，隐藏菜单不能代替业务检查。

## 切换模式

管理员通过系统设置中的“切换使用方式”进入功能安装页，选择目标模式并安装。接口在目标组合全部就绪后才更新当前模式；失败时保持原模式。

切换保留已安装的其他插件、用户、套餐、订单、余额、兑换码和配置，不自动卸载插件，也不覆盖已有账户。可以继续在插件中心单独管理额外扩展。需要关闭推广时应停用 `affiliate`。

商业插件收到 `workspace.configured` 后，根据当前模式控制公开套餐；用户前台的套餐、订单与钱包入口也只在商业模式且商业插件启用时显示。切出商业模式后，原有商业数据保留。

注册政策与模式独立。已安装并启用的 `registration` 仅按全局“开放注册”设置决定新账号注册，不随模式切换暗中改变。关闭注册或停用注册插件后，已有 OAuth 绑定登录和已登录用户的第三方账号绑定仍可用；新 OAuth 账号还需对应提供方允许注册。

模式通知和默认账户创建由后台事件队列处理，模式完成后可能存在短暂的业务入口更新延迟。已有用户会话、历史订单和管理员处理记录不会因模式切换自动删除；如需停用某项插件或暂停某个账户，应分别执行对应操作。

## 模式接口

模式管理需要管理员身份：

| 接口                | 用途                                       |
| ------------------- | ------------------------------------------ |
| `GET /api/v1/mode`  | 查询当前模式、目标模式、来源和逐项安装状态 |
| `POST /api/v1/mode` | 启动所选组合的后台安装与启用               |

请求可以指定已注册的 `sourceId`，或指定 `sourceUrl`：

```json
{
  "mode": "business",
  "sourceUrl": "https://plugins.example.com/index.json"
}
```

启动成功返回 HTTP `202`，不表示所有插件已经就绪。客户端继续读取状态；`phase` 为 `needs_install`、`installing`、`ready` 或 `failed`。插件项目分别包含标识、名称、状态和可能的错误。

`mode` 是当前激活方式，`requestedMode` 是本次目标方式。只有 `phase=ready` 且当前模式与目标相同时才表示切换完成。重复点击安装不能替代读取当前任务结果；同一时刻已有安装运行时，服务端拒绝重复启动。
